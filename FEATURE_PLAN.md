# Взаиморасчёты, черновики и приготовление

## Решения

- Покупка за свои уже включена в строки расходов. Запись финансирования не увеличивает стоимость готовки.
- Поддерживаются зачёт и отдельный возврат. Долг и выполненный перевод учитываются раздельно; для старой покупки можно записать уже выполненный возврат с датой.
- Баланс: получено − начислено + куплено за свои − возвращено + корректировки. Зачёт применяется после Legacy-расчёта; отрицательный результат показывается как сумма к возврату.
- Настройки приготовления задаются в блюде и копируются в новую готовку. Изменения блюда не меняют историю.
- Количество изделий задаётся явно, независимо от денежных коэффициентов. Комбинация хранит количество, участника и пожелания.
- Кратность проверяется по сумме одного значения настройки у всех участников. Нарушение вызывает предупреждение, сохранение разрешено.
- Визуальная сводка: карточки комбинаций с количеством и участниками, индикаторы партий; для взаиморасчётов — карточки сумм и схема зачёта/возврата.
- Черновики хранятся в текущем браузере с разделением по аккаунту и записи. Ошибки сервера не удаляют введённое; старая версия не перезаписывает новую.

## Работы

1. Агент черновиков: хранилище, готовки, справочники и формы балансов, проверки восстановления и ошибок.
2. Агент взаиморасчётов: покупки и датированные возвраты, миграция, API, контроль версии, недельные балансы и расчёт выбранных готовок.
3. Агент приготовления: настройки блюда, snapshot готовки, комбинации, кратность, визуальная сводка, API и миграция.
4. Оркестратор: интеграция, визуальные взаиморасчёты и статистика, проверка контрактов и общие проверки.

## Приёмка

- Начисление 300, покупка 200 с зачётом: собрать 100.
- Начисление 300, покупка 500 с зачётом: вернуть 200; выполненный возврат 200 закрывает остаток.
- Начисление 300, покупка 500 отдельным переводом: собрать 300 и вернуть 500; выполненный перевод снимает обязательство вернуть.
- Возврат следующей неделей отображается по фактической дате, даже если готовка вне выбранного периода.
- Обновление страницы восстанавливает незавершённый ввод; ошибка сохраняет черновик; успешное сохранение очищает его.
- Два бургера одного участника можно распределить на разные прожарки, сохраняя для обоих исключение помидоров.
- Пять medium и пять well done образуют допустимые партии независимо от овощей; девять и один вызывают предупреждение.
- Изменения блюда не меняют историческую готовку; пожелания не меняют денежного расчёта.

Исторические суммы и даты вводятся отдельно пользователем. Публикация релиза и изменение производственных данных в текущую работу не входят. Дополнительные разделы сохраняются для уже созданной готовки отдельными командами с общей защитой версии.
